# Examples

Six worked examples, each runnable as it stands. All outputs below were produced
by running the code shown.

Set up once:

```python
import math
import torch
from torchdiffeq import odeint
from torchdiffeq.jump import (
    CoupledStochasticJumpMechanism, FixedJumpMechanism, JumpMechanism,
    SimpleStochasticJumpMechanism, odeint_jump_adjoint,
)
torch.set_default_dtype(torch.float64)
```

---

## 1. Prescribed events — a dosing schedule

The simplest case: a decaying state that receives a fixed dose at known times.

```python
class Decay(torch.nn.Module):
    def forward(self, t, y):
        return -0.5 * y

class Dose(torch.nn.Module):
    def forward(self, t, z):
        return torch.full_like(z, 1.0)

t = torch.linspace(0.0, 6.0, 7)
mechanism = FixedJumpMechanism(
    torch.tensor([1.5, 3.5]),   # event times
    torch.ones(2, 2),           # (batch, n_events): both doses given to both
)
y = odeint(Decay(), torch.zeros(2, 1), t, method="dopri5",
           options={"jump": Dose(), "jump_mechanism": mechanism})
print([round(v, 4) for v in y[:, 0, 0].tolist()])
```

```
[0.0, 0.0, 0.7788, 0.4724, 1.0653, 0.6461, 0.3919]
```

Read it against the closed form: nothing until the first dose, then
$e^{-0.5 \times 0.5} = 0.7788$ at $t=2$; the second dose lands on
$e^{-0.5 \times 2} = 0.3679$, giving $1.3679$, which decays to $1.0653$ at
$t=4$. The doses land exactly at 1.5 and 3.5, not at the nearest step boundary,
because prescribed times are merged into the integration grid.

## 2. Latent projection — keeping a hazard out of the jump

A survival-style model carries a cumulative hazard $\Lambda$ alongside the
latent state. The jump must move the latent state and leave $\Lambda$ alone.

```python
LATENT, N_HAZARDS = 2, 1

class HazardDynamics(torch.nn.Module):
    def forward(self, t, y):
        d = torch.zeros_like(y)
        d[..., :LATENT] = -0.3 * y[..., :LATENT]                    # dz/dt
        d[..., LATENT:] = torch.nn.functional.softplus(y[..., :1])  # dLambda/dt
        return d

class Bump(torch.nn.Module):
    def forward(self, t, z):
        return torch.ones_like(z)

mechanism = FixedJumpMechanism(
    torch.tensor([1.0]), torch.ones(1, 1),
    latent_proj=lambda y: y[..., :LATENT],   # a *view*, so the jump writes back
)
y = odeint(HazardDynamics(), torch.zeros(1, LATENT + N_HAZARDS),
           torch.tensor([0.0, 1.0, 2.0]), method="dopri5",
           options={"jump": Bump(), "jump_mechanism": mechanism})

print("latent :", [round(v, 4) for v in y[:, 0, 0].tolist()])
print("Lambda :", [round(v, 4) for v in y[:, 0, -1].tolist()])
```

```
latent : [0.0, 1.0, 0.7408]
Lambda : [0.0, 0.6931, 1.9094]
```

The latent state jumps to 1 at $t = 1$ — the reported value at the event time is
the *post*-jump state, which is the càdlàg convention. $\Lambda$ does not jump:
it is continuous through the event. Its *slope* changes, because
$\lambda = \mathrm{softplus}(z_0)$ and $z_0$ just moved — that is the model
working, not a leak.

Drop the `latent_proj` and $\Lambda$ would be displaced too, and
$S(t) = e^{-\Lambda(t)}$ would stop being a survival function.

## 3. Stochastic sampling — a Poisson process

Events generated by the model rather than supplied to it. A constant hazard must
produce a Poisson process, which is a sharp check on the sampler.

```python
RATE, HORIZON, BATCH = 1.5, 6.0, 500

class ConstantHazard(torch.nn.Module):
    def forward(self, t, y):
        d = torch.zeros_like(y)
        d[..., 1:] = RATE          # dLambda/dt; the latent coordinate is frozen
        return d

class Unit(torch.nn.Module):
    def forward(self, t, z):
        return torch.ones_like(z)  # each event adds one, so y[0] counts them

mechanism = SimpleStochasticJumpMechanism(
    batch_shape=(BATCH,),
    cumulative_hazards_proj=lambda t, y: y[..., 1],
    rng=torch.Generator().manual_seed(0),
    latent_proj=lambda y: y[..., :1],
)
y = odeint(ConstantHazard(), torch.zeros(BATCH, 2),
           torch.tensor([0.0, HORIZON]), method="dopri5",
           options={"jump": Unit(), "jump_mechanism": mechanism})

counts = y[-1, :, 0]
print(f"E[N(T)]={counts.mean():.3f}  Var={counts.var():.3f}  expected={RATE*HORIZON}")
```

```
E[N(T)]=8.982  Var=9.356  expected=9.0
```

Mean and variance both match $\lambda T = 9$, as a Poisson count must.

## 4. Competing risks — coupled event types

Several event streams race, each with its own hazard, its own column of the jump
map, and its own cap.

```python
LATENT, N_TYPES = 2, 3
RATES = torch.tensor([0.4, 0.8, 0.2])

class Competing(torch.nn.Module):
    """Latent state is frozen; each event type accrues its own hazard."""
    def forward(self, t, y):
        d = torch.zeros_like(y)
        d[..., LATENT:] = RATES
        return d

class PerTypeJump(torch.nn.Module):
    """Event type k displaces the latent state by k + 1."""
    def forward(self, t, z):
        steps = torch.arange(1, N_TYPES + 1, dtype=z.dtype)
        return torch.ones(*z.shape, N_TYPES, dtype=z.dtype) * steps

mechanism = CoupledStochasticJumpMechanism(
    batch_shape=(4,),
    coupling_dim=N_TYPES,
    cumulative_hazards_proj=lambda t, y: y[..., LATENT:],
    rng=torch.Generator().manual_seed(1),
    latent_proj=lambda y: y[..., :LATENT],
    max_events=[1, 2, 1],            # per type, not per trajectory
)
y = odeint(Competing(), torch.zeros(4, LATENT + N_TYPES),
           torch.tensor([0.0, 10.0]), method="dopri5",
           options={"jump": PerTypeJump(), "jump_mechanism": mechanism})

for i, events in enumerate(mechanism._realised_events):
    print(f"trajectory {i}: " +
          ", ".join(f"t={float(a):.3f} type={b}" for a, b in events))
```

```
trajectory 0: t=1.867 type=1, t=2.005 type=1, t=6.990 type=0, t=7.257 type=2
trajectory 1: t=0.734 type=1, t=0.993 type=1, t=4.328 type=0
trajectory 2: t=0.431 type=1, t=0.856 type=1, t=1.936 type=0, t=2.726 type=2
trajectory 3: t=0.841 type=1, t=1.114 type=1, t=1.750 type=0, t=5.550 type=2
```

Type 1 has the highest rate and fires first and twice; every trajectory respects
the per-type caps `[1, 2, 1]`. Trajectory 1 never fired type 2 within the
horizon — with $\lambda_2 = 0.2$ over 10 time units that is unremarkable.

**`max_events` is per type.** Three types capped at 2 allow six events on one
trajectory, not two.

## 5. Adjoint gradients

The jump ODE $dz/dt = az$ with $z \to z(1+b)$ has the closed form
$z(T) = z_0 e^{aT}(1+b)$, so gradients can be checked exactly.

```python
class Linear(torch.nn.Module):
    def __init__(self):
        super().__init__()
        self.a = torch.nn.Parameter(torch.tensor(0.5))
    def forward(self, t, y):
        return self.a * y

class Scale(torch.nn.Module):
    def __init__(self):
        super().__init__()
        self.b = torch.nn.Parameter(torch.tensor(0.3))
    def forward(self, t, z):
        return self.b * z

def run(solve):
    f, h = Linear(), Scale()
    z0 = torch.ones(1, 1, requires_grad=True)
    mechanism = FixedJumpMechanism(torch.tensor([0.4]), torch.ones(1, 1))
    extra = ({"adjoint_params": tuple(f.parameters()) + tuple(h.parameters())}
             if solve is odeint_jump_adjoint else {})
    out = solve(f, z0, torch.tensor([0.0, 1.0]), method="dopri5",
                rtol=1e-10, atol=1e-12,
                options={"jump": h, "jump_mechanism": mechanism}, **extra)
    out[-1].sum().backward()
    return out[-1].item(), z0.grad.item(), f.a.grad.item(), h.b.grad.item()

print("direct  z=%.10f dz0=%.10f da=%.10f db=%.10f" % run(odeint))
print("adjoint z=%.10f dz0=%.10f da=%.10f db=%.10f" % run(odeint_jump_adjoint))
```

```
analytic z(1)=2.1433376519  dz/db=1.6487212707
direct  z=2.1433376520 dz0=2.1433376520 da=2.1433376530 db=1.6487212708
adjoint z=2.1433376520 dz0=2.1433376519 da=2.1433376520 db=1.6487212708
```

Both agree with the closed form to nine digits, and the jump network's parameter
`b` receives a gradient. Swap in `odeint_adjoint` and `db` comes back exactly
`0.0` with no error raised — that is the failure this function exists to avoid.

In a training loop, `odeint_jump_adjoint` is a drop-in for `odeint_adjoint`:

```python
optimiser = torch.optim.Adam([*f.parameters(), *h.parameters()], lr=1e-3)
for batch in loader:
    mechanism = FixedJumpMechanism(batch.event_times, batch.event_mask,
                                   coupled=True, latent_proj=project)
    pred = odeint_jump_adjoint(f, batch.y0, batch.t, method="dopri5",
                               options={"jump": h, "jump_mechanism": mechanism})
    loss = criterion(pred, batch.y)
    optimiser.zero_grad(); loss.backward(); optimiser.step()
```

Build a **fresh mechanism per batch** — a mechanism is stateful and is consumed
by the solve.

## 6. A custom mechanism — bouncing ball

Events that are neither prescribed nor hazard-driven. A ball falls under gravity
and reverses velocity on contact with the ground, losing energy each time. The
event condition is a state crossing, so the mechanism implements
`next_event_time` itself.

```python
GRAVITY, RESTITUTION = 9.81, 0.8

class Ballistic(torch.nn.Module):
    def forward(self, t, y):                      # y = (height, velocity)
        return torch.stack([y[..., 1],
                            torch.full_like(y[..., 0], -GRAVITY)], dim=-1)

class Bounce(torch.nn.Module):
    """Reverse and damp the velocity; the height is unchanged."""
    def forward(self, t, y):
        return torch.stack([torch.zeros_like(y[..., 0]),
                            -(1 + RESTITUTION) * y[..., 1]], dim=-1)

class GroundContact(JumpMechanism):
    def __init__(self):
        super().__init__(batch_dims=0)

    @property
    def kind(self):
        return "simple"

    def next_event_time(self, z_interp, t0, t1, tol=1e-9):
        """First time in (t0, t1] at which the height reaches zero."""
        if z_interp(t1)[..., 0] > 0:
            return None                            # monotone predicate: one test
        lo, hi = torch.as_tensor(t0), torch.as_tensor(t1)
        while (hi - lo) > tol:
            mid = (lo + hi) / 2
            if z_interp(mid)[..., 0] <= 0:
                hi = mid
            else:
                lo = mid
        return hi

    def realise_event(self, t, z):
        return torch.ones((), dtype=z.dtype)       # the single stream fires

y = odeint(Ballistic(), torch.tensor([5.0, 0.0]), torch.linspace(0, 4, 9),
           method="dopri5", rtol=1e-9, atol=1e-11,
           options={"jump": Bounce(), "jump_mechanism": GroundContact()})
print("height:", [round(v, 4) for v in y[:, 0].tolist()])
```

```
height: [5.0, 3.7737, 0.095, 2.706, 3.0364, 0.9142, 1.6872, 1.7913, 0.3854]
```

The ball bounces and each apex is lower than the last. No `latent_proj` is
needed: the jump acts on the whole state.

Two things to be aware of when writing a contact mechanism like this:

- **The predicate must be monotone within a step** for the single test at `t1`
  to be a sound existence check. Here it is while the ball is falling. If yours
  is not, replace that test with a search that suits your condition — the
  contract only asks for the earliest event in `(t0, t1]`.
- **Chattering.** As the bounces shrink, contacts crowd together and a physical
  Zeno point is approached; a real simulation adds a minimum inter-event time or
  a resting condition. `MAX_EVENTS_PER_STEP` (1024) is a backstop against a
  mechanism that stops making progress, not a substitute for that.
